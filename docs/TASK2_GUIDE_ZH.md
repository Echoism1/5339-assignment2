## 本次代码怎么运行

具体命令见主 README。使用 `conda activate ai312`。依次启动 broker、subscriber，看到 `READY` 后再启动 publisher。默认 topic 是 `comp5339/TUT19-AssignmentGroup-08/events`，取自本地 A1 包的组号；最终必须全组一致。如果实际组号更换，同步设置两端 `--topic` 和订阅器 `--client-id`。

`READY` 表示已收到 QoS 1 SUBACK，不只是 TCP 连接成功。首次启动前的非 retained 消息无法被追溯，因此顺序很重要。完整发布约四分多钟；缩短测试只用于故障场景，不能替代正式全量验收。

## 接收处理逻辑

1. Paho 接收 QoS 1 消息，放入有界内存队列，默认最多 512 条。回调不执行数据库操作。
2. 唯一 writer 线程拥有 DuckDB，避免多个写入者争用连接。
3. 严格解码 UTF-8 和 JSON，拒绝重复 JSON key、NaN/Infinity、缺失或未知字段、错误数值类型、无时区时间、非法 SoC、连接器范围错误及事件哈希不符。批发电价允许为负；布尔值不会冒充整数。
4. 站点必须在生成输入中，并能匹配 A1 的 DC `ev_id`、连接器数及坐标。收到的字符串 `station_id` 精确匹配后才转换为 A1 BIGINT，保留原 JSON 供核查。
5. 有效事件以 `event_id` 主键去重，写入 `core.mqtt_event`，外键直接指向 A1 的 `core.charger_record(ev_id)`。表和静态数据在同一数据库、同一 `core` schema。
6. 异常消息的原始字节以 Base64 存入 `core.mqtt_rejection`，附 topic、原因、接收时间；它们不会污染有效事件表。
7. 有效写入或异常隔离提交后才手动 ACK。数据库故障时停止且不确认未提交消息；不要把 publisher 的 broker ACK 当成消费成功。

QoS 1 本身允许重复，所以本实现是至少一次传输加持久化幂等落库，不宣称网络端到端 exactly-once。重复回放仍只有 2,452 条唯一事件。重新收到同一个历史事件不会删除后续状态；成员 3 应按事件时间计算当前态，不按网络到达时间盲目覆盖。

订阅器使用稳定 client ID、MQTT 3.1.1 persistent session，断线按 1 至 30 秒退避自动重连，每次重新订阅。Broker 必须保留 session 才能补送离线队列；测试用 Python broker 重启会丢失 session，所以仍需重新发布遗漏窗口。Mosquitto 配置有持久化，Docker volume 保存 broker 状态，但突然断电、有限队列和未及时刷盘仍不意味着无限可靠。最可靠的作业恢复方式是重新播放原窗口，由数据库去重。

如果接收队列满，程序停止并报错，不静默丢弃后继续假装成功。修复下游吞吐后用同一 client ID 重启，必要时重新发布窗口。Ctrl+C 停止接收并处理已排队消息。历史事件即使晚到仍会保存，writer 不会强制要求会话开始必须先到；成员 3 应处理重复、晚到、缺失开始以及半开窗口的未完成会话。

## 与成员 3 和成员 4 的衔接

输出边界是已提交的 `core.mqtt_event` 与对应的 `event_id`。它保留全部事件字段，没有删除实时曲线所需的电压、电流、功率、累计能量或 SoC。不要对累计 `energy_kwh` 求和。会话结束表示拔枪，`charge_end_ts` 可以更早；窗口末九个未结束会话应保留活跃状态。

`core.mqtt_charger_events` 提供已关联的站点名称、地址、坐标、类型、连接器数、运营商 ID 和 SA4 编码。更多 A1 属性可通过原 `analytics.chargers`、`core.charger_plug` 等表查询。没有会话的站点仍应在地图出现，不能只从会话表建立站点全集。

**DuckDB 多进程约束需要团队明确处理。** 单独的 Streamlit 进程不能在 subscriber 持有写锁时直接打开同一数据库。成员 3/4 联调可采用同一个 Python 服务进程：writer 持有写连接，其他线程建立同文件独立连接供只读查询，通过 API 给前端；或由服务定期导出原子只读快照供仪表盘查询。当前成员 2 包没有偷偷声称已经实现该 API 或仪表盘。单独运行 SQL 检查前先停止 subscriber。

成员 3 如果增加派生状态表，应把 inbox 插入和状态更新纳入同一事务，全部提交后才 ACK；保留 `event_id` 唯一约束。A1 原有表、外键、空间列与增强证据应继续保留，不要用简单 CSV 重新建站点表替换 A1 关系模式。初始化只复制原数据库，并添加三项接收对象，不修改原 A1 文件。
